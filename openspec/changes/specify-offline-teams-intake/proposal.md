## Why

Teams-originated intent needs a precise privacy and non-authority contract before
any future connector can feed the private GitHub lifecycle. The human selected
specification-only Teams work on 2026-11-26 alongside a separately scoped synthetic
offline GitHub adapter. Neither track proves a working Teams integration.

## What Changes

- Specify minimal, authorized user-supplied intent, trusted private routing and
  pre-write source/content/audience checks.
- Separate conversational intent, immutable issue capture, proposed registry
  admission and later exact human scope authorization.
- Specify default detail-free feedback, separately proven private detail delivery,
  review navigation, duplicate handling and visible unknown/reconciliation states.
- Bound optional standard GitHub Teams app and Channel Agent/MCP paths by verified
  public documentation and outstanding live capability proof.
- Preserve GitHub as system of record and every existing independent gate.

## Capabilities

### New Capabilities

- `teams-intake-contract`: Future Teams intent normalization into a permitted
  private GitHub solution issue/capture, safe feedback and review navigation.

### Modified Capabilities

None. This refines the pending `add-teams-experience-layer` boundary without
modifying it or claiming accepted baseline specifications.

## Impact

Only this new OpenSpec subtree changes. Main owns shared references and integration
with `build-offline-github-intake`. No connector, approval bridge, authorization
join, durable coordinator, code, tests, setup, subscription, consent, tenant access,
model execution or deployment is authorized here. Structural validation is not
human acceptance or live readiness.
